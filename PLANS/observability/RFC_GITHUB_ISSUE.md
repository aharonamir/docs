## RFC: Complete Observability Coverage For DeepAgent, Sessions, Metrics, And Cost

### Summary

This RFC proposes completing the repository's observability work in incremental
phases. The repository already has meaningful OpenTelemetry support for
team-agent runs, standalone BaseAgent/workflow tracing through
`openjiuwen/extensions/tracer_otel/`, Claude/Codex bridge tracing, and a local
Langfuse/collector deployment stack. The remaining work should focus on filling
coverage gaps rather than replacing the current implementation.

The main missing capability is opt-in tracing for standalone `DeepAgent` runs.
Additional useful work includes ordered trajectory events, disabled-by-default
OTel metrics, cost/usage aggregation, and carefully bounded session root spans.

Source plan: `docs/observability/PLAN.md`

### Current State

What already exists:

- Team-agent OTel tracing under `openjiuwen/agent_teams/observability/`.
- `init_observability()`, `shutdown_observability()`,
  `finalize_team_trace()`, and `attach_to_team_agent()`.
- Team root spans, member task iteration spans, invoke spans, LLM spans, tool
  spans, task/member/message monitor spans, and cancellation cleanup through
  `ActiveSpanTracker`.
- Standalone BaseAgent/workflow OTel extension under
  `openjiuwen/extensions/tracer_otel/`.
- Claude bridge tracing under `openjiuwen/agent_teams/observability/claude/`.
- Codex rollout/OTLP bridge tracing under
  `openjiuwen/agent_teams/observability/codex/`.
- Local Langfuse v3 and OTel collector support under `deploy/observability/`.

Important constraints:

- `ObservabilityRail` now has real lifecycle logic and should be extended, not
  bypassed.
- Standalone `DeepAgent` tracing still does not work because
  `ObservabilityRail` skips span creation when no team span exists.
- `create_deep_agent()` and `resolve_deep_agent_parts()` do not currently
  accept `observability_config`.
- `SessionEvents.AGENT_SESSION_CREATED` exists, but there is no symmetric
  session-close event in the callback event enum.
- There is no OTel metrics infrastructure yet.
- Token usage is recorded on spans, but no cost model or rollup exists.

### Goals

- Preserve the current team-agent tracing contract.
- Add explicit opt-in observability for standalone `DeepAgent`.
- Make traces easier to inspect by recording ordered per-iteration LLM/tool
  trajectory events.
- Add metrics in a disabled-by-default configuration path.
- Add best-effort cost and usage aggregation with explicit uncertainty for
  unknown models.
- Add session root spans only with a clear lifecycle/finalization strategy.

### Non-Goals

- Replacing the existing team observability provider.
- Making metrics enabled by default.
- Creating a new durable trajectory store in the tracing hot path.
- Pretending model costs are exact or stable without versioned pricing config.
- Leaving long-lived session spans open indefinitely.

### Proposed Phases

#### Phase 0: Audit Tests And Freeze The Current Contract

Add or update tests proving:

- Team trace parent tree stays intact.
- Subagent invoke spans still nest correctly.
- Cancellation cleanup drains orphaned child spans.
- Codex/Claude bridge tests continue to pass.
- Shutdown remains idempotent.

Estimated effort: 1-2 days.

#### Phase 1: Standalone DeepAgent OTel

Add:

- `observability_config: ObservabilityConfig | None = None` to
  `resolve_deep_agent_parts()` and `create_deep_agent()`.
- Factory wiring that calls `init_observability()` when needed and appends
  `ObservabilityRail()` unless an equivalent rail was supplied.
- A standalone root span path in `ObservabilityRail` when there is no team span.
- LLM/tool parent resolution against the current standalone agent/root span.

Expected trace shape:

```text
agent.{card.name}
  └── agent.{card.name}.task_iteration.N
      ├── llm.call
      └── tool.{name}
```

Estimated effort: 3-5 days.

#### Phase 2: Session Root Spans

Add:

- `session_span.py` with a `SessionSpanManager`.
- Open span on `SessionEvents.AGENT_SESSION_CREATED`.
- Parent resolution that prefers an open session span before creating team or
  standalone roots.
- Explicit cleanup from `shutdown_observability()` and team/agent finalization
  paths.

Open design point:

- The repository currently has a session creation event but no close event.
  Either add a close event at the actual lifecycle owner, or explicitly bound
  session spans by finalization/shutdown paths.

Estimated effort: 4-8 days.

#### Phase 3: Ordered Trajectory Events

Add:

- `trajectory_tracker.py`.
- Close-time `record_llm_step()` and `record_tool_step()` calls from
  `OtelCallbackHandler`.
- `emit_to_span()` from `ObservabilityRail.after_task_iteration()` before the
  iteration span ends.

Start with span events:

```text
trajectory.step {seq: 1, kind: "llm", model: "...", prompt_tokens: 123}
trajectory.step {seq: 2, kind: "tool", name: "bash", duration_ms: 812}
```

Estimated effort: 2-4 days.

#### Phase 4: OTel Metrics

Add:

- `metrics_enabled: bool = False`.
- `metrics_endpoint: str = ""`.
- `metrics_exporter: Literal["otlp_grpc", "otlp_http", "console"]`.
- `metrics.py` with a `MeterProvider` and small recorder API.
- Collector metrics pipeline and Prometheus/Grafana wiring in
  `deploy/observability/`.

Initial instruments:

- `llm.token_usage` counter.
- `llm.call.duration` histogram.
- `tool.call.duration` histogram.
- `tool.call.errors` counter.
- `deepagent.task.iteration.duration` histogram.
- `deepagent.task.iteration.errors` counter.

Estimated effort: 4-8 days.

#### Phase 5: Cost And Aggregation

Add:

- `cost_tracker.py` with a versioned model pricing table.
- Unknown-model behavior that sets token totals but omits or marks cost as
  unknown/estimated.
- Task/member aggregation for prompt tokens, completion tokens, tool calls,
  errors, duration, and estimated cost.
- Task/team/session attributes for totals.

Example attributes:

```text
agentteam.task.total_prompt_tokens
agentteam.task.total_completion_tokens
agentteam.task.total_tool_calls
agentteam.task.estimated_cost_usd
agentteam.task.cost_pricing_version
agentteam.task.member_contributions
```

Estimated effort: 4-8 days.

### Recommended Implementation Order

Recommended order:

1. Phase 0
2. Phase 1
3. Phase 3
4. Phase 5
5. Phase 4
6. Phase 2

Rationale:

- Phase 1 closes the largest functional coverage gap.
- Phase 3 and Phase 5 build on existing span facts with limited lifecycle risk.
- Phase 4 adds operational value but requires exporter/deploy plumbing.
- Phase 2 is valuable but should wait until the session close/finalization model
  is clear.

### Acceptance Criteria

- Existing team-agent observability tests continue to pass.
- Standalone `DeepAgent` can emit root, iteration, LLM, and tool spans when
  explicitly opted in.
- Observability shutdown remains idempotent and closes open child/root spans.
- Iteration spans can include ordered LLM/tool trajectory events.
- Metrics are disabled by default and do not affect tracing-only users.
- Cost estimates are versioned, overrideable, and explicit about unknown models.
- Session spans are never left open without a documented finalization path.
